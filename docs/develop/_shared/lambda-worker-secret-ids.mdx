An API key secret contains the key as a plain string. Certificate and private key secrets contain PEM. To load mTLS
credentials, set the client certificate and client private key IDs together. If one secret contains the certificate and
private key, use its ID for both settings. Set the server CA certificate ID if you need a custom CA. Keep TLS enabled
when you use TLS secret IDs.

For each secret ID, the Lambda environment variable overrides the corresponding TOML setting.

When you configure an API key secret ID, remove any `TEMPORAL_API_KEY` setting from the Lambda function's environment
and any `api_key` setting from the TOML profile. The
[direct-key deployment example](/production-deployment/worker-deployments/serverless-workers/aws-lambda#deploy-lambda-function-step)
sets that environment variable. The Worker fails at startup if you set a secret ID and a direct value or file path for
the same credential, even across environment variables and TOML.

The Worker retrieves secrets through the
[AWS Parameters and Secrets Lambda Extension](https://docs.aws.amazon.com/secretsmanager/latest/userguide/retrieving-secrets_lambda.html)
when available. Otherwise, it uses the AWS SDK.

Grant the Lambda execution role [permission to read the secrets](/production-deployment/worker-deployments/serverless-workers/aws-lambda#use-aws-secrets-manager).
