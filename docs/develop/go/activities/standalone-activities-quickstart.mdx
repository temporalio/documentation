# Quickstart

Standalone Activities are Activity Executions that run independently, without being orchestrated by a Workflow. Instead
of starting an Activity from within a Workflow Definition using `workflow.ExecuteActivity()`, you start a Standalone
Activity directly from a Temporal Client using `client.ExecuteActivity()`.

The Activity definition and Worker registration are identical to regular Activities, and only the execution path
differs.

:::note

This documentation uses source code from the
[go-sandbox/activities/standalone](https://github.com/temporalio/documentation-sdk-code-examples/tree/main/go-sandbox/activities/standalone)
sample.

:::

## Get started with Standalone Activities {/* #get-started */}

Prerequisites:

- **[Go](https://go.dev/dl/)** 1.26+, the version the sample's `go.mod` requires

- **[Temporal Go SDK](/develop/go/set-up-your-local-go#install-the-temporal-go-sdk)** (v1.49.0 or higher)

- **Temporal CLI** v1.9.1 or higher. Install with Homebrew, or see the [Temporal CLI install guide](/cli/setup-cli) for other platforms. Verify the installation with `temporal --version`.

Start the Temporal development server with `temporal server start-dev`.

This command automatically starts the Temporal development server with the Web UI, and creates the `default` Namespace.
It uses an in-memory database, so do not use it for real use cases.

The Temporal Server should now be available for client connections on `localhost:7233`, and the
Temporal Web UI should now be accessible at [http://localhost:8233](http://localhost:8233).

</SetupStep>

<SetupStep>

<CodeSnippet title="worker/main.go">

<!--SNIPSTART go-standalone-activity-quickstart-worker-->
[go-sandbox/activities/standalone/worker/main.go](https://github.com/temporalio/documentation-sdk-code-examples/blob/main/go-sandbox/activities/standalone/worker/main.go)
```go
package main

import (
	"log"

	"go.temporal.io/sdk/client"
	"go.temporal.io/sdk/contrib/envconfig"
	"go.temporal.io/sdk/worker"

	"my-org/quickstart/activities/standalone"
)

func main() {
	c, err := client.Dial(envconfig.MustLoadDefaultClientOptions())
	if err != nil {
		log.Fatalln("Unable to create client", err)
	}
	defer c.Close()

	// Registering a Standalone Activity is the same as registering any other Activity.
	w := worker.New(c, standalone.TaskQueue, worker.Options{})
	w.RegisterActivity(standalone.Activity)

	if err := w.Run(worker.InterruptCh()); err != nil {
		log.Fatalln("Unable to start Worker", err)
	}
}
```

## Run a Worker with the Activity registered {/* #run-worker */}

Running a Worker for Standalone Activities is the same as running a Worker for Workflow-driven Activities — you create a
Worker, register the Activity, and call `Run()`. The Worker doesn't need to know whether the Activity will be invoked
from a Workflow or as a Standalone Activity.

See [Develop a Worker in Go](/develop/go/workers/run-worker-process#develop-worker) for more details on Worker setup and
configuration options.

Open a new terminal, switch to the `go-sandbox` directory, and run the Worker.
Leave this terminal running - the Worker needs to stay up to process Activities.

</SetupStep>

## Execute a Standalone Activity {/* #execute-activity */}

Use [`client.ExecuteActivity()`](https://pkg.go.dev/go.temporal.io/sdk/client#Client) to start a Standalone Activity
Execution. This is called from application code (for example, a starter program), not from inside a Workflow Definition.

`ExecuteActivity` returns an [`ActivityHandle`](https://pkg.go.dev/go.temporal.io/sdk/client#ActivityHandle) that you
can use to get the result, describe, cancel, or terminate the Activity.
The starter calls `handle.Get()` to wait for the Activity to finish and read its result.

`client.StartActivityOptions` requires `ID`, `TaskQueue`, and at least one of `ScheduleToCloseTimeout` or
`StartToCloseTimeout`. See [`StartActivityOptions`](https://pkg.go.dev/go.temporal.io/sdk/client#StartActivityOptions)
in the API reference for the full set of options.

To run the starter:

1. Make sure the Temporal Server is running (from the [Get Started](#get-started) step above).
2. Make sure the Worker is running (from the [Run a Worker](#run-worker) step above).
3. Open a new terminal, switch to the `go-sandbox` directory, and run:
    ```
    go run ./activities/standalone/starter
    ```

The last line of output shows the result:

```
Activity result: Hello Temporal!
```

Or use the Temporal CLI to execute a Standalone Activity.

</SetupStep>

## Execute a Standalone Activity by type name {/* #execute-activity-by-name */}

You can pass the Activity to `ExecuteActivity` as a function reference, as in the previous step, or as a string
Activity type name.
Use the type name when the code that starts the Activity can't import the Activity function, for example when the
Activity is written in another language.

The type name of a Go Activity registered with `RegisterActivity` is the function name, `Activity` in this sample.

</SetupStep>

## List and count Standalone Activities {/* #list-activities */}

Use [`client.ListActivities()`](https://pkg.go.dev/go.temporal.io/sdk/client#Client) and
[`client.CountActivities()`](https://pkg.go.dev/go.temporal.io/sdk/client#Client) to find and count the Standalone
Activity Executions that match a [List Filter](/list-filter) query.
These APIs return only Standalone Activity Executions. Activities running inside Workflows are not included.

Run the starter with `-command list` to list the Activities on the sample's Task Queue, and with `-command count` to
count them.
See [List Standalone Activities](/develop/go/activities/standalone-activities#list-activities) in the feature guide for
more about the query syntax.

## Run with Temporal Cloud

All code samples on this page use
[`envconfig.MustLoadDefaultClientOptions()`](https://pkg.go.dev/go.temporal.io/sdk/contrib/envconfig)
to configure the Temporal Client connection. It responds to [environment
variables](/references/client-environment-configuration) and [TOML configuration
files](/references/client-environment-configuration), so the same code works against a local dev
server and Temporal Cloud without changes. See [Run Standalone Activities with Temporal
Cloud](/develop/go/activities/standalone-activities#run-standalone-activities-temporal-cloud) in the feature guide
for mTLS and API key setup.
