# Standalone Activities Go Quickstart

<ReleaseNoteHeader
  featureName="standaloneActivity"
/>

A [Standalone Activity](/develop/go/activities/standalone-activities) is an Activity Execution that runs on its own, without being orchestrated by a Workflow. Instead of starting an Activity from within a Workflow Definition with `workflow.ExecuteActivity()`, you start it directly from a Temporal Client with `client.ExecuteActivity()`. The Activity Definition and Worker registration are identical to a regular Activity — only the execution path differs.

**Prerequisites:**

- **[Go](https://go.dev/dl/)** 1.22 or higher
- **[Temporal Go SDK](/develop/go/set-up-your-local-go#install-the-temporal-go-sdk)** v1.41.0 or higher
- **Temporal CLI** v1.7.0 or higher (`brew install temporal`, or see the [CLI install guide](/cli/setup-cli))
- A local Temporal development server running (`temporal server start-dev`)

Clone the [samples-go](https://github.com/temporalio/samples-go) repository to follow along:

```bash
git clone https://github.com/temporalio/samples-go.git
cd samples-go
```

The files you build in this guide live under `standalone-activity/helloworld/`.

## What you'll build

By the end of this guide:

1. An Activity Definition that both a Worker and a starter can share.
2. A Worker that registers the Activity and polls for tasks.
3. A starter that executes the Activity directly from a Temporal Client and prints `Hello Temporal!` — no Workflow involved.

## 1. Define your Activity

Create a file called `activity.go` that defines the Activity.

Define the Activity in a shared package so that both the Worker and the starter can reference it. A Standalone Activity Definition is no different from an Activity you would call from a Workflow — it's an ordinary Go function that takes a `context.Context` and returns a result and an error.

`Activity` takes a `name` and returns a greeting string. The `activity.GetLogger` call writes to the Activity logger so you can see the invocation in the Worker output.

</SetupStep>

<SetupStep code={
<>

<CodeSnippet language="go" title="worker/main.go">
{`package main

import (
    "log"

    "github.com/temporalio/samples-go/standalone-activity/helloworld"
    "go.temporal.io/sdk/client"
    "go.temporal.io/sdk/contrib/envconfig"
    "go.temporal.io/sdk/worker"
)

func main() {
    c, err := client.Dial(envconfig.MustLoadDefaultClientOptions())
    if err != nil {
        log.Fatalln("Unable to create client", err)
    }
    defer c.Close()

    w := worker.New(c, "standalone-activity-helloworld", worker.Options{})

    w.RegisterActivity(helloworld.Activity)

    err = w.Run(worker.InterruptCh())
    if err != nil {
        log.Fatalln("Unable to start worker", err)
    }
}`}
</CodeSnippet>

</>
}>

## 2. Run a Worker

Create a file called `worker/main.go` that runs a Worker with the Activity registered.

Running a Worker for Standalone Activities is the same as running one for Workflow-driven Activities: create a Worker, register the Activity, and call `Run()`. The Worker doesn't need to know whether the Activity will be invoked from a Workflow or as a Standalone Activity. See [How to develop a Worker in Go](/develop/go/workers/run-worker-process#develop-worker) for more on Worker setup.

`envconfig.MustLoadDefaultClientOptions()` configures the Client connection from [environment variables or a TOML profile](/references/client-environment-configuration), so the same code works against a local dev server and Temporal Cloud without changes.

Open a new terminal, navigate to the `samples-go` directory, and run the Worker:

```
go run standalone-activity/helloworld/worker/main.go
```

Leave this terminal running — the Worker needs to stay up to process Activities.

</SetupStep>

<SetupStep code={
<>

<CodeSnippet language="go" title="starter/main.go">
{`package main

import (
    "context"
    "log"
    "time"

    "github.com/temporalio/samples-go/standalone-activity/helloworld"
    "go.temporal.io/sdk/client"
    "go.temporal.io/sdk/contrib/envconfig"
)

func main() {
    c, err := client.Dial(envconfig.MustLoadDefaultClientOptions())
    if err != nil {
        log.Fatalln("Unable to create client", err)
    }
    defer c.Close()

    activityOptions := client.StartActivityOptions{
        ID:                     "standalone_activity_helloworld_ActivityID",
        TaskQueue:              "standalone-activity-helloworld",
        ScheduleToCloseTimeout: 10 * time.Second,
    }

    handle, err := c.ExecuteActivity(context.Background(), activityOptions, helloworld.Activity, "Temporal")
    if err != nil {
        log.Fatalln("Unable to execute activity", err)
    }

    log.Println("Started standalone activity", "ActivityID", handle.GetID(), "RunID", handle.GetRunID())

    var result string
    err = handle.Get(context.Background(), &result)
    if err != nil {
        log.Fatalln("Unable get standalone activity result", err)
    }
    log.Println("Activity result:", result)
}`}
</CodeSnippet>

</>
}>

## 3. Execute a Standalone Activity

Create a file called `starter/main.go` that executes the Activity from a Temporal Client.

Use [`client.ExecuteActivity()`](https://pkg.go.dev/go.temporal.io/sdk/client#Client) to start a Standalone Activity Execution. This is called from application code — not from inside a Workflow Definition.

`client.StartActivityOptions` requires `ID`, `TaskQueue`, and at least one of `ScheduleToCloseTimeout` or `StartToCloseTimeout`. `ExecuteActivity` returns an [`ActivityHandle`](https://pkg.go.dev/go.temporal.io/sdk/client#ActivityHandle) that you use to get the result, describe, cancel, or terminate the Activity. `handle.Get()` blocks until the Activity completes and deserializes the result into the provided pointer, analogous to calling `Get()` on a `WorkflowRun`.

</SetupStep>

<SetupStep code={
<>

<CodeSnippet language="bash">
go run standalone-activity/helloworld/starter/main.go
</CodeSnippet>

</>
}>

## 4. Run and Verify

With the Worker still running from step 2, open a new terminal, navigate to the `samples-go` directory, and run the starter.

You should see output similar to:

```
2026/01/15 10:00:00 Started standalone activity ActivityID standalone_activity_helloworld_ActivityID RunID 1f2e3d4c-5b6a-7890-abcd-ef1234567890
2026/01/15 10:00:00 Activity result: Hello Temporal!
```

You can also execute a Standalone Activity with the Temporal CLI instead of the starter:

```bash
temporal activity execute \
  --type Activity \
  --activity-id standalone_activity_helloworld_ActivityID \
  --task-queue standalone-activity-helloworld \
  --schedule-to-close-timeout 10s \
  --input '"Temporal"'
```

Open the [Temporal Web UI](http://localhost:8233) and select **Activities** from the nav bar to see the Execution you just started.
